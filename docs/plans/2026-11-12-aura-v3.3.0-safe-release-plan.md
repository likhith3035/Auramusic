# AuraMusic v3.3.0 Safe Release Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Safely release AuraMusic v3.3.0 (versionCode 34) with photorealistic celestial weather and live network telemetry, ensuring zero secrets, credentials, or private keys are ever committed or pushed to Git.

**Architecture:** A multi-stage release pipeline with strict pre-commit secrets isolation, synchronized version bump across mobile/desktop Gradle manifests and update checker metadata, in-app changelog expansion, local production APK assembly and signing, and targeted explicit file staging.

**Tech Stack:** Kotlin Multiplatform, Gradle (Android Application & Compose Desktop), Git, Android apksigner, JSON metadata.

---

### Strict Security & Secrets Protection Principles

1. **Zero Blind Staging:** Never execute `git add .` or `git add -A`. Every file must be explicitly added by its full relative path.
2. **Ignored Credentials Isolation:** Verify that `local.properties`, `keystore.properties`, `*.jks`, `*.keystore`, `.env`, and `release/` directories are completely ignored and not tracked by Git index.
3. **Automated Secret Scan:** Run an automated regex inspection on all staged files before creating any commit to ensure no API keys, private passwords, or keystore files are included.
4. **Separation of Release Binaries:** Release APKs (`.apk`) and distribution archives (`.zip`) are generated into the gitignored `release/` directory for GitHub Releases attachment, never committed into repository history.
5. **Zero Unicode Emojis:** Maintain strict compliance with the project standard of 0 Unicode emojis across all code, documentation, and metadata files.
